# DKNet DDD Conventions

DKNet is DrunkCoding open-source .NET framework: https://github.com/baoduy/DKNet (MIT).

## READ THIS FIRST — the docs lie

DKNet's `docs/*.md` files carry note *"generated by the 'copilot' 100%"* and **contradict real source in several places**. Verified divergences:

| DKNet `docs/` says | Source actually says |
|---|---|
| `IHook.OnPreSaveChangesAsync` | `IBeforeSaveHookAsync.BeforeSaveAsync(SnapshotContext, ct)` |
| `IRepository<T>.Gets()` / `.GetByIdAsync()` | `IReadRepository<T>.Query()` / `.FindAsync()` |

**Never cite `docs/` or `baoduy.github.io/DKNet` as contract.** Verify against `src/` on **`dev`** branch (not `main` — `dev` is default). Table below was transcribed from source and is reference of record for this skill.

## Contract surface (verified from source)

### Entities — `DKNet.EfCore.Abstractions.Entities`
- `IEntity<TKey>` → `TKey Id { get; }`
- `Entity<TKey>` / `Entity` (Guid) — abstract base, implements `IEntity<TKey>` + `IEventEntity`
- `IAuditedProperties` → `CreatedOn`, `UpdatedOn`, `CreatedBy`, `UpdatedBy`
- `AuditedEntity<TKey>` / `AuditedEntity` — protected `SetCreatedBy(user, on?)`, `SetUpdatedBy(user, on?)`; exposes `LastModifiedBy`/`LastModifiedOn`
- `IConcurrencyEntity<T>` → `RowVersion` (`[Timestamp]`), `SetRowVersion(...)`
- `ISoftDeletableEntity` → `IsDeleted`, `DeletedOn`, `DeletedBy`, `Delete(byUser, on?) : IResultBase`
- Attributes: `[StaticData]`, `[IgnoreEntityMapper]`, `[SqlSequence]`

### Domain events — `DKNet.EfCore.Abstractions.Events`
- `IEventEntity` → `AddEvent(object)`, `AddEvent<TEvent>()`, `GetEvents() : (object[], Type[])`, `ClearEvents()`
- `EventItem` (abstract record) → `EventType`, `AdditionalData`
- `IEventPublisher` → `PublishAsync(object, ct)` + bulk overload

### Repositories — `DKNet.EfCore.Repos.Abstractions`
- `IReadRepository<T>` → `CountAsync`, `ExistsAsync`, `FindAsync(key)`, `FindAsync(object[])`, `FindAsync(filter)`, `Query()`, `Query(filter)`, `Query<TModel>(filter)`
- `IWriteRepository<T>` → `AddAsync`, `AddRangeAsync`, `Delete`, `DeleteRange`, `Entry()`, `UpdateAsync`, `UpdateRangeAsync`, `SaveChangesAsync`, `BeginTransactionAsync`
- `IRepository<T> : IReadRepository<T>, IWriteRepository<T>`
- `IRepositoryFactory` → `Create<T>()`, `CreateRead<T>()`, `CreateWrite<T>()`

### Specifications — `DKNet.EfCore.Specifications`
- `Specification<T>` → `FilterQuery`, `IncludeQueries`, `IncludeBuilders`, `OrderByQueries`, `OrderByDescendingQueries`, `IsIgnoreQueryFilters`
- Protected builders: `AddInclude`, `AddOrderBy`, `AddOrderByDescending`, `IgnoreQueryFilters`, `CreatePredicate()` → LinqKit `ExpressionStarter<T>`
- `ModelSpecification<T,TModel>`, `IRepositorySpec`, `IRepositorySpecFactory`, `PageAsyncEnumerator` (X.PagedList)

### Hooks — `DKNet.EfCore.Hooks`
- `IBeforeSaveHookAsync.BeforeSaveAsync(SnapshotContext, ct)`
- `IAfterSaveHookAsync.AfterSaveAsync(SnapshotContext, ct)`
- `IHookAsync` = both; `HookAsync` = no-op base

### Data authorization — `DKNet.EfCore.DataAuthorization`
- `IOwnedBy` → `string OwnedBy { get; }`
- `IDataOwnerProvider` → `GetAccessibleKeys()`, `GetOwnershipKey()`
- `IDataOwnerDbContext` → `AccessibleKeys` (drives global query filters)

### CQRS — `DKNet.SlimBus.Extensions`, static class `Fluents`
- `Fluents.Requests.IWitResponse<T> : IRequest<IResult<T>>`, `INoResponse : IRequest<IResultBase>`
- `Fluents.Requests.IHandler<TRequest>` / `IHandler<TRequest,TResponse>`
- `Fluents.Queries.IWitResponse<T>` / `IWitPageResponse<T>`, `IHandler<,>` / `IPageHandler<,>`
- `Fluents.EventsConsumers.IHandler<TEvent> : IConsumer<TEvent>`
- `EfAutoSavePostInterceptor` auto-calls `SaveChangesAsync` after command handlers
- **FluentResults** (`IResult` / `IResultBase`) is return discipline — not exceptions

## Violation patterns to flag

Each carries a stable `rule-id`. Use these verbatim as finding fingerprints.

### Aggregate & entity design
- `DKNET-AGG-001` **Anaemic aggregate.** Entity is only auto-properties; all state transitions live in handlers/services. Behaviour belongs on aggregate.
- `DKNET-AGG-002` **Public setter on entity property.** Entities expose `set;` instead of `private set;` + an intention-revealing method (`Activate()`, `Suspend(reason)`).
- `DKNET-AGG-003` **Exposed mutable collection.** Navigation returns `ICollection<T>`/`List<T>` directly instead of `IReadOnlyCollection<T>` over a private backing field.
- `DKNET-AGG-004` **Cross-aggregate object reference.** An aggregate holds a reference to another aggregate root instead of its id. Reference by id across aggregate boundaries.
- `DKNET-AGG-005` **Aggregate over budget.** Aggregate file exceeds ~400 lines or holds >8 child collections — a boundary is probably wrong.
- `DKNET-AGG-006` **Primitive obsession.** Money/currency/email/phone/code carried as `decimal`/`string` where a value object (record) belongs.
- `DKNET-AGG-007` **Public parameterless constructor** on an entity, letting callers build invalid state. EF materialisation needs a *private* one.
- `DKNET-AGG-008` **Manual key assignment.** `Id` set by caller instead of `Guid.CreateVersion7()` / configured value generator.

### Domain events
- `DKNET-EVT-001` **Event raised outside aggregate.** Handler calls `AddEvent` on someone else's entity instead of aggregate raising it in its own state transition.
- `DKNET-EVT-002` **Event carries entity.** Event payload embeds tracked entity rather than ids + values that changed.
- `DKNET-EVT-003` **Event handler mutating a foreign aggregate** without going through a command.

### Repository & query
- `DKNET-REPO-001` **Over-broad repository injection.** `IRepository<T>` (read+write) injected where only reads happen — should be `IReadRepository<T>`.
- `DKNET-REPO-002` **Spec bypass.** Ad-hoc `Query().Where(...)` chains in handlers duplicating logic that a `Specification<T>` already encodes or should encode.
- `DKNET-REPO-003` **Duplicate specification.** Two specs with equivalent predicates — collapse.
- `DKNET-REPO-004` **`DbContext` injected into `AppServices`.** Application layer must go through repositories/specs.
- `DKNET-REPO-005` **Manual `SaveChangesAsync` in a command handler** where `EfAutoSavePostInterceptor` already saves — double save / partial transaction risk.
- `DKNET-REPO-006` **Redundant `UpdateAsync` on a tracked entity.** Entity came from `FindAsync`/`Query()`/a spec on a repository *without* `AsNoTracking()`, so change tracker already holds it: mutating aggregate is enough and `SaveChangesAsync` (via `EfAutoSavePostInterceptor`) persists diff. `await repo.UpdateAsync(entity, ct)` on that entity is dead code — and not harmlessly so: `Update` marks **every** property `Modified`, so unchanged columns get written back (clobbering concurrent writes) and audit/hook diffs widen from fields that changed to whole row. **Delete call.**
  `UpdateAsync` is *only* for a **detached** entity — exactly three cases: query used `AsNoTracking()` (or `IgnoreQueryFilters` + no-tracking spec), entity was loaded on a *different* `DbContext`/scope (e.g. `IMonxaRepositorySpecFactory` in an event handler), or it was reconstructed from a DTO/message payload rather than read. Anything else: tracked, no call.
  Reviewers: this is a delete-on-sight finding, not a discussion — cite `DKNET-REPO-006` and point at read that produced entity. Authors: if you think you need it, check query for `AsNoTracking()` first.

### Layering
- `DKNET-LAYER-001` **Domain depends on infrastructure.** `Domains` project referencing EF Core provider types, HTTP clients, or `Infra`.
- `DKNET-LAYER-002` **Business logic in API layer.** Endpoint does more than map request → bus message → response.
- `DKNET-LAYER-003` **Infra reaching into AppServices.**
- `DKNET-LAYER-004` **Partner client types leaking into Domain or public DTOs.**

### Results & errors
- `DKNET-RES-001` **Exception used for expected business failure** where FluentResults `IResult` is convention.
- `DKNET-RES-002` **Result ignored.** `IResultBase` returned and discarded without checking `IsFailed`.

### Data authorization
- `DKNET-AUTH-001` **Merchant/tenant-owned entity missing ownership marker** (`IOwnedBy` / solution's `IMerchantOwnedEntity`) — row-level filter silently does not apply.
- `DKNET-AUTH-002` **`IgnoreQueryFilters()` in a spec** without a comment justifying why tenant filter is bypassed.

## Solution-local conventions (Monxa payment gateway)

These extend, not replace, above. Source: repo's own `CLAUDE.md`.

- Layers: `Api` (HTTP + CLI jobs) → `AppServices` (all business logic) → `Domains` (no infra deps); `Infra` (DbContexts, migrations, repos, Service Bus); `Share` (cross-cutting); client projects per partner.
- Handlers inject `IRepositorySpec`, not `IRepository<T>`. Event handlers needing an independent unit-of-work use `IMonxaRepositorySpecFactory`.
- Feature folders: `AppServices/Features/<Feature>/{Actions,Queries,Services,EventHandlers,Specs}`.
- Keys are `Guid` UUIDv7 via `GuidV7ValueGenerator`, wired by `DefaultEfCoreConfig<T>` — never set manually.
- Schemas via constants only: `InfraConsts.PaymentSchema` (`pgw`), `.StaticDataSchema` (`static`), `.NostroSchema` (`nostro`).
- `[GenerateDto(typeof(Entity), Exclude = [...])]` must exclude **every** navigation property — an un-excluded nav leaks entity into DTO and cycles break OpenAPI generation.
- Amount rounding is global via `AmountRoundingInterceptor<>` — never round inside a handler.
- Every state-changing `POST` needs `.RequiredIdempotentKey()`.
- Domain-event handlers implement `Fluents.EventsConsumers.IHandler<TEvent>` under `Features/<Feature>/EventHandlers/`.

## Authoring reference — canonical shapes

Rule tables above are written as "what to flag". This section is same rules from author's side: copy these shapes and violations cannot happen. Docs follow `DOC-*` in `dotnet10-efcore10-standards` skill.

### An aggregate root

```csharp
/// <summary>
/// A merchant's settlement batch: the unit the gateway pays out and reconciles against.
/// A batch is mutable only while <c>Open</c>; closing it freezes the lines for reconciliation.
/// </summary>
public sealed class SettlementBatch : AuditedEntity, IOwnedBy
{
    private readonly List<SettlementLine> _lines = [];

    /// <summary>EF materialisation only. Use <see cref="Open"/> — it is the only path that yields a valid batch.</summary>
    private SettlementBatch() { }

    /// <summary>Opens a batch for a merchant's payout currency. Raises <see cref="BatchOpenedEvent"/>.</summary>
    public static SettlementBatch Open(string merchantId, Currency currency, string byUser) { /* ... */ }

    /// <summary>Lines in this batch. Read-only — add through <see cref="AddLine"/> so the total stays consistent.</summary>
    public IReadOnlyCollection<SettlementLine> Lines => _lines;

    /// <summary>Running total of <see cref="Lines"/>. Maintained on mutation, never recomputed by callers.</summary>
    public Money Total { get; private set; }

    /// <summary>Adds a line and updates <see cref="Total"/>.</summary>
    /// <returns>Failure when the batch is closed, or when the line's currency differs from the batch's.</returns>
    public IResultBase AddLine(Guid paymentId, Money amount)
    {
        if (Status != BatchStatus.Open) return Result.Fail("Batch is closed.");
        // ... mutate, then raise from inside the transition — never from a handler
        AddEvent(new BatchLineAddedEvent(Id, paymentId, amount.Value));
        return Result.Ok();
    }
}
```

Every rule this shape satisfies: `DKNET-AGG-001` (behaviour on aggregate) · `-002` (`private set`) · `-003` (`IReadOnlyCollection` over a private list) · `-004` (`Guid paymentId`, not a `Payment`) · `-006` (`Money`, `Currency` value objects) · `-007` (private ctor + static factory) · `-008` (no manual `Id`) · `DKNET-EVT-001/002` (event raised inside transition, carries ids + values) · `DKNET-RES-001` (FluentResults, not exceptions) · `DKNET-AUTH-001` (`IOwnedBy`).

### A query handler

```csharp
/// <summary>Returns the merchant's open batches, newest first, for the payouts dashboard.</summary>
internal sealed class GetOpenBatchesHandler(IRepositorySpec repo)
    : Fluents.Queries.IPageHandler<GetOpenBatches, BatchDto>
{
    /// <inheritdoc/>
    public async Task<IPagedList<BatchDto>> OnHandle(GetOpenBatches request, CancellationToken ct) =>
        await repo.SpecsPageAsync<SettlementBatch, BatchDto>(new OpenBatchesSpec(request.MerchantId), request.Page, ct);
}
```

`IRepositorySpec`, not `IRepository<T>` (`DKNET-REPO-001`) · predicate lives in `OpenBatchesSpec`, not inline (`DKNET-REPO-002`) · no `SaveChangesAsync` — `EfAutoSavePostInterceptor` owns it (`DKNET-REPO-005`) · `ct` forwarded (`ASYNC-001`) · projects to `BatchDto`, does not materialise graph (`EFC-009`).

### A command handler that mutates

```csharp
/// <summary>Adds a line to an open batch.</summary>
internal sealed class AddBatchLineHandler(IRepositorySpec repo)
    : Fluents.Requests.IHandler<AddBatchLine>
{
    /// <inheritdoc/>
    public async Task<IResultBase> OnHandle(AddBatchLine request, CancellationToken ct)
    {
        var batch = await repo.FindAsync<SettlementBatch>(request.BatchId, ct);
        if (batch is null) return Result.Fail("Batch not found.");

        var result = batch.AddLine(request.PaymentId, request.Amount);

        // No UpdateAsync: `batch` is tracked (the read had no AsNoTracking), so the
        // mutation is already staged and EfAutoSavePostInterceptor saves it (DKNET-REPO-006).
        // No SaveChangesAsync either (DKNET-REPO-005).
        return result;
    }
}
```

Detached counter-example — *only* shape where call belongs:

```csharp
// AsNoTracking ⇒ detached ⇒ tracker has never seen `batch`, so it must be attached.
var batch = await repo.Query<SettlementBatch>().AsNoTracking().FirstOrDefaultAsync(ct);
batch.Close(user);
await repo.UpdateAsync(batch, ct);
```

### DRY, concretely

Before writing a predicate, a mapping, or a validation: grep feature slice's `Specs/` folder and `Share/` first. Three duplications that actually recur here:

- **Same `Where(...)` in two handlers** → one `Specification<T>`, both call it. Not "similar" — identical predicates only; forcing two near-predicates into one parameterised spec is worse than duplication.
- **Same guard in every handler of a feature** → move it onto aggregate as an invariant, or into a `IBeforeSaveHookAsync`. A guard repeated in handlers means aggregate is letting invalid state exist.
- **Same entity→DTO projection hand-written twice** → `[GenerateDto(typeof(Entity), Exclude = [...])]`, and exclude *every* navigation property.

Two occurrences is a note; three is `CLEAN-DRY-001` and gets extracted. Copy-paste that has already drifted (`CLEAN-DRY-002`) gets extracted at two, because drift is bug.
