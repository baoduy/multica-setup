# DKNet DDD Conventions

DKNet is DrunkCoding open-source .NET framework: https://github.com/baoduy/DKNet (MIT).

## READ THIS FIRST — docs lie

DKNet's `docs/*.md` files carry note *"generated by the 'copilot' 100%"* and **contradict real source in several places**. Verified divergences:

| DKNet `docs/` says | Source actually says |
|---|---|
| `IHook.OnPreSaveChangesAsync` | `IBeforeSaveHookAsync.BeforeSaveAsync(SnapshotContext, ct)` |
| `IRepository<T>.Gets()` / `.GetByIdAsync()` | `IReadRepository<T>.Query()` / `.FindAsync()` |

**Never cite `docs/` or `baoduy.github.io/DKNet` as contract.** Verify against `src/` on **`dev`** branch (not `main` — `dev` is default). Table below was transcribed from source and is reference of record for this skill.

## Contract surface (verified from source)

### Entities — `DKNet.EfCore.Abstractions.Entities`
- `IEntity<TKey>` → `TKey Id { get; }`
- `Entity<TKey>` / `Entity` (Guid) — abstract base, implements `IEntity<TKey>` + `IEventEntity`
- `IAuditedProperties` → `CreatedOn`, `UpdatedOn`, `CreatedBy`, `UpdatedBy`
- `AuditedEntity<TKey>` / `AuditedEntity` — protected `SetCreatedBy(user, on?)`, `SetUpdatedBy(user, on?)`; exposes `LastModifiedBy`/`LastModifiedOn`
- `IConcurrencyEntity<T>` → `RowVersion` (`[Timestamp]`), `SetRowVersion(...)`
- `ISoftDeletableEntity` → `IsDeleted`, `DeletedOn`, `DeletedBy`, `Delete(byUser, on?) : IResultBase`
- Attributes: `[StaticData]`, `[IgnoreEntityMapper]`, `[SqlSequence]`

### Domain events — `DKNet.EfCore.Abstractions.Events`
- `IEventEntity` → `AddEvent(object)`, `AddEvent<TEvent>()`, `GetEvents() : (object[], Type[])`, `ClearEvents()`
- `EventItem` (abstract record) → `EventType`, `AdditionalData`
- `IEventPublisher` → `PublishAsync(object, ct)` + bulk overload

### Repositories — `DKNet.EfCore.Repos.Abstractions`
- `IReadRepository<T>` → `CountAsync`, `ExistsAsync`, `FindAsync(key)`, `FindAsync(object[])`, `FindAsync(filter)`, `Query()`, `Query(filter)`, `Query<TModel>(filter)`
- `IWriteRepository<T>` → `AddAsync`, `AddRangeAsync`, `Delete`, `DeleteRange`, `Entry()`, `UpdateAsync`, `UpdateRangeAsync`, `SaveChangesAsync`, `BeginTransactionAsync`
- `IRepository<T> : IReadRepository<T>, IWriteRepository<T>`
- `IRepositoryFactory` → `Create<T>()`, `CreateRead<T>()`, `CreateWrite<T>()`

### Specifications — `DKNet.EfCore.Specifications`
- `Specification<T>` → `FilterQuery`, `IncludeQueries`, `IncludeBuilders`, `OrderByQueries`, `OrderByDescendingQueries`, `IsIgnoreQueryFilters`
- Protected builders: `AddInclude`, `AddOrderBy`, `AddOrderByDescending`, `IgnoreQueryFilters`, `CreatePredicate()` → LinqKit `ExpressionStarter<T>`
- `ModelSpecification<T,TModel>`, `IRepositorySpec`, `IRepositorySpecFactory`, `PageAsyncEnumerator` (X.PagedList)

### Hooks — `DKNet.EfCore.Hooks`
- `IBeforeSaveHookAsync.BeforeSaveAsync(SnapshotContext, ct)`
- `IAfterSaveHookAsync.AfterSaveAsync(SnapshotContext, ct)`
- `IHookAsync` = both; `HookAsync` = no-op base

### Data authorization — `DKNet.EfCore.DataAuthorization`
- `IOwnedBy` → `string OwnedBy { get; }`
- `IDataOwnerProvider` → `GetAccessibleKeys()`, `GetOwnershipKey()`
- `IDataOwnerDbContext` → `AccessibleKeys` (drives global query filters)

### CQRS — `DKNet.SlimBus.Extensions`, static class `Fluents`
- `Fluents.Requests.IWitResponse<T> : IRequest<IResult<T>>`, `INoResponse : IRequest<IResultBase>`
- `Fluents.Requests.IHandler<TRequest>` / `IHandler<TRequest,TResponse>`
- `Fluents.Queries.IWitResponse<T>` / `IWitPageResponse<T>`, `IHandler<,>` / `IPageHandler<,>`
- `Fluents.EventsConsumers.IHandler<TEvent> : IConsumer<TEvent>`
- `EfAutoSavePostInterceptor` auto-calls `SaveChangesAsync` after command handlers
- **FluentResults** (`IResult` / `IResultBase`) is return discipline — not exceptions

## Violation patterns to flag

Each carries stable `rule-id`. Use these verbatim as finding fingerprints.

### Aggregate & entity design
- `DKNET-AGG-001` **Anaemic aggregate.** Entity is only auto-properties; all state transitions live in handlers/services. Behaviour belongs on aggregate.
- `DKNET-AGG-002` **Public setter on entity property.** Entities expose `set;` instead of `private set;` + intention-revealing method (`Activate()`, `Suspend(reason)`).
- `DKNET-AGG-003` **Exposed mutable collection.** Navigation returns `ICollection<T>`/`List<T>` directly instead of `IReadOnlyCollection<T>` over private backing field.
- `DKNET-AGG-004` **Cross-aggregate object reference.** Aggregate holds reference to another aggregate root instead of its id. Reference by id across aggregate boundaries.
- `DKNET-AGG-005` **Aggregate over budget.** Aggregate file exceeds ~400 lines or holds >8 child collections — boundary is probably wrong.
- `DKNET-AGG-006` **Primitive obsession.** Money/currency/email/phone/code carried as `decimal`/`string` where value object (record) belongs.
- `DKNET-AGG-007` **Public parameterless constructor** on entity, letting callers build invalid state. EF materialisation needs *private* one.
- `DKNET-AGG-008` **Manual key assignment.** `Id` set by caller instead of `Guid.CreateVersion7()` / configured value generator.

### Domain events
- `DKNET-EVT-001` **Event raised outside aggregate.** Handler calls `AddEvent` on someone else's entity instead of aggregate raising it in its own state transition.
- `DKNET-EVT-002` **Event carries entity.** Event payload embeds tracked entity rather than ids + values that changed.
- `DKNET-EVT-003` **Event handler mutating foreign aggregate** without going through command.

### Repository & query
- `DKNET-REPO-001` **Over-broad repository injection.** `IRepository<T>` (read+write) injected where only reads happen — should be `IReadRepository<T>`.
- `DKNET-REPO-002` **Spec bypass.** Ad-hoc `Query().Where(...)` chains in handlers duplicating logic that `Specification<T>` already encodes or should encode.
- `DKNET-REPO-003` **Duplicate specification.** Two specs with equivalent predicates — collapse.
- `DKNET-REPO-004` **`DbContext` injected into `AppServices`.** Application layer must go through repositories/specs.
- `DKNET-REPO-005` **Manual `SaveChangesAsync` in command handler** where `EfAutoSavePostInterceptor` already saves — double save / partial transaction risk.

### Layering
- `DKNET-LAYER-001` **Domain depends on infrastructure.** `Domains` project referencing EF Core provider types, HTTP clients, or `Infra`.
- `DKNET-LAYER-002` **Business logic in API layer.** Endpoint does more than map request → bus message → response.
- `DKNET-LAYER-003` **Infra reaching into AppServices.**
- `DKNET-LAYER-004` **Partner client types leaking into Domain or public DTOs.**

### Results & errors
- `DKNET-RES-001` **Exception used for expected business failure** where FluentResults `IResult` is convention.
- `DKNET-RES-002` **Result ignored.** `IResultBase` returned and discarded without checking `IsFailed`.

### Data authorization
- `DKNET-AUTH-001` **Merchant/tenant-owned entity missing ownership marker** (`IOwnedBy` / solution's `IMerchantOwnedEntity`) — row-level filter silently does not apply.
- `DKNET-AUTH-002` **`IgnoreQueryFilters()` in spec** without comment justifying why tenant filter is bypassed.
